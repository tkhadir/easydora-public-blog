# Release Notes — 2026-03-07

## Overview

This release delivers significant improvements to the DORA metrics charts, GitHub API reliability, and overall stability of the application.

---

## New Features

### Time-Bucketed "Trends Over Time" Charts

Previously the charts plotted stored database calculation snapshots, which often produced only 1–2 flat data points (all calculated on the same day). Charts now display how each DORA metric **changes over time** within the selected measurement period.

**How it works:**
- The measurement period is automatically divided into time buckets based on duration:
  - ≤ 7 days → daily buckets
  - 8–14 days → 2-day buckets
  - 15–90 days → weekly buckets
  - > 90 days → bi-weekly buckets
- 3 GitHub REST API calls are made per page load (merged PRs, releases, bug issues) and bucketed in-memory — no extra database writes required
- Each data point shows deployment frequency (deploys/day), lead time for changes (avg hrs), mean time to recovery (avg hrs), and change failure rate (%)
- Tooltips display the bucket label (e.g. `Jan 01 – Jan 07`), PR count, and deployment count for that period

**Affected pages:** `/metrics` (per-repository) and `/global-metrics` (all repositories)

### Global Metrics Charts Overhaul

The `/global-metrics` page previously used 4 separate D3.js charts (deployment frequency, lead time, MTTR, change failure rate). These are now replaced with a single unified **Chart.js** line chart consistent with the per-repository metrics page.

- Trend data is fetched concurrently for up to 8 repositories, then aggregated:
  - Deployment frequency is **summed** (total global deploys/day)
  - Lead time, MTTR, and change failure rate are **averaged** across repositories
- Chart subtitle shows the measurement period and repository count
- Removed D3.js dependency from the global metrics page

## Bug Fixes

### Quick Check — 401 Bad Credentials Error

The Quick Check page was returning `401 Bad credentials` even for public repositories when the system GitHub token was invalid or absent.

**Fix:** Added a 3-level token fallback chain:
1. **User OAuth token** — used if the logged-in user has a valid connected GitHub account
2. **System token** — falls back to the server-configured `GITHUB_TOKEN`
3. **Unauthenticated REST** — if both tokens fail or are absent, uses the GitHub REST API without authentication (works for public repositories)

### Quick Check — 403 Rate Limit Exceeded

After the 401 fix introduced an unauthenticated GraphQL fallback, GitHub's GraphQL API returned `403 Forbidden` because it requires authentication even for public repository queries.

**Fix:** The unauthenticated fallback path now uses the **GitHub REST API** exclusively (`CalculateQuickMetricsREST`), which supports unauthenticated access for public repositories without hitting GraphQL rate limits.

## Improvements

### Chart Library Consistency

Both the per-repository metrics page and the global metrics page now use the same chart stack:
- **Chart.js 4.4.0** — unified charting library
- **chartjs-adapter-date-fns 3.0.0** — time-axis date formatting
- **chartjs-plugin-annotation 3.0.1** — release markers on the per-repository chart

Release tags are annotated as vertical dashed lines on the per-repository trends chart.

### Dual Y-Axis Layout

Charts now use dual y-axes for clarity:
- Left axis: Deployment Frequency (deploys/day)
- Right axis: Lead Time and MTTR (hours)
- Change failure rate (%) uses a hidden third axis to avoid distorting the scale
